# Supabase setup

Apply these scripts in the Supabase Dashboard SQL Editor, using **Run as postgres**:

1. `storefront-images.sql` creates the homepage image records, public image bucket, and admin-only upload/edit/delete policies.
2. `blog-posts.sql` creates or updates the blog table for one Big featured post and unlimited Small posts, with public reads and admin-only publishing controls. Existing posts are retained as Small when this migration first adds the post type. Blog images can be uploaded from a device to the `storefront-images` bucket created by step 1, or supplied as a public image URL.
3. `products.sql` creates or updates the public product catalog with admin-only create/edit/delete access, product categories, multiple images, regular and special pricing, quantity price tiers, and sales/view counters for the automatic home-page featured feed. Product images use the `storefront-images` bucket from step 1, or can be entered as public URLs. Re-run it to migrate an existing catalog to these fields.
4. `orders.sql` creates an admin-managed order table, order items, customer-owned order history, checkout order creation with a server-generated order number, a restricted tracking lookup, and triggers that keep product sales counts current. Checkout requires an email and validates item prices and stock against the catalog. New orders appear in the admin Orders section as Pending. Sales count only when an order is confirmed, processing, shipped, or delivered. Customers can see their own orders while public tracking reveals status only when both the order number and phone number match.
5. `customer-accounts.sql` creates customer profiles and private per-user carts. It excludes users with `app_metadata.role = 'admin'` from customer profiles and saves a profile for each customer registration. A guest cart is copied into the customer's Supabase cart the first time they sign in. The customer app uses a separate browser auth storage key so the admin browser session does not appear as a customer session.

After all five scripts succeed, reload the store and the admin dashboard. If you already ran an earlier version of `orders.sql`, run the updated file again before `customer-accounts.sql` so the order owner, item fields, and sales-count triggers are added. Product detail views are counted at most once per browser per product every 30 minutes. The home page automatically mixes newest, best-selling, most-visited, and discounted products; offers currently use product special prices and can be connected to a separate offers system later. Re-run `blog-posts.sql` when applying the Big/Small post update. If the admin role was just granted to your account, sign out and sign in again before uploading or publishing.

Checkout submissions create pending orders automatically. Older orders can still be entered through the Supabase Table Editor with the customer's Auth user ID in `orders.user_id` and line items in `order_items`; these appear in the customer's order history and admin Orders section.

Uploads are limited to image files up to 10 MB. The `storefront-images` bucket is public so the storefront can display uploaded banners without a signed-in visitor; only accounts with `app_metadata.role = 'admin'` can upload, replace, or delete files.
